## Solution
Apparently, gnomes tampered with the neighborhood's Santa-tracking service and it no longer runs on port 8080. I was tasked to find the new port the <code>santa_tracker</code> process is using and connect to that port to verify that the service is running.

![Terminal request context](../img/objectives/o3/Screenshot%202025-12-29%20085433.png)

### Enumeration

I ran the command <code>ss -tlnp</code> to list all listening ports and the processes using them.

<code>ss</code> command flag roles: <br/>
<code>-t</code>: Shows TCP sockets <br/>
<code>-l</code>: Shows ports actively waiting for incoming connections <br/>
<code>-n</code>: Shows numeric address and port numbers instead of service names (0.0.0.0:ss instead of 0.0.0.0:ssh) <br/>
<code>-p</code>: Shows the process associated with the socket <br/>

![Enumeration detail 1](../img/objectives/o3/Screenshot%202025-12-29%20085920.png)

!!! warning "Key finding"
    The command shows that there is only one process running on local address and port <code>0.0.0.0:12321</code>

So I ran the command <code>curl http://localhost:12321</code> to test if the service was actually running on that port.

### Validation and Completion

The <code>curl</code> command returned the Santa-tracking service response and a special note: <br/>
