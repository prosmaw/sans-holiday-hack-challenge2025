## Objective

    Help Goose Lucas in the hotel parking lot find the dangerously misconfigured Network Security Group rule that's allowing unrestricted internet access to sensitive ports like RDP or SSH.

## Solution

Lucas asked me audit the Dosis Neighborhood's Azure network security configuration for potential overly permissive NSG rules .

The terminal session introduced the challenge and the Azure CLI environment.

![Screenshot 2026-04-21 121230](../img/objectives/o9/Screenshot%202026-04-21%20121230.png)

The first task was to list resource groups using the command:

~~~bash linenums="1" title="List resource groups"
az group list
~~~

The output listed the available resource groups which are <code>theneighborhood-rg1</code> and <code>theneighborhood-rg2</code>. 

![Screenshot 2026-04-21 121429](../img/objectives/o9/Screenshot%202026-04-21%20121429.png)

The next task was to list resource groups in table format with the command:

~~~bash linenums="1" title="List resource groups (table)"
az group list -o table
~~~

The table made it easier to spot the neighborhood resource groups.

![Screenshot 2026-04-21 121455](../img/objectives/o9/Screenshot%202026-04-21%20121455.png)

Task 3 asked to list network security groups using the command:

~~~bash linenums="1" title="List NSGs"
az network nsg list -o table
~~~

The output showed all NSGs and the resource group they are attached to.

![Screenshot 2026-04-21 121601](../img/objectives/o9/Screenshot%202026-04-21%20121601.png)

The next tasks from here asked to inspect al NSGs and spot the one with the with bad configuration. The first NSG to inspect was the web NSG for <code>theneighborhood-rg1</code>. 
I used the following command:

~~~bash linenums="1" title="Show nsg-web-eastus"
az network nag show --name nsg-web-eastus --resource-group theneighborhood-rg1 | less
~~~

The details shows all rules of the web NSG but no particular rule with overly permissible access.

![Screenshot 2026-04-21 121949](../img/objectives/o9/Screenshot%202026-04-21%20121949.png)

Additional details from the previous NSG output confirmed it was not the issue.

![Screenshot 2026-04-21 122034](../img/objectives/o9/Screenshot%202026-04-21%20122034.png)

I inspected others NSGs including the management NSG using this command:

~~~bash linenums="1" title="Show nsg-mgmt-eastus"
az network nag show --name nsg-mgmt-eastus --resource-group theneighborhood-rg2 | less
~~~

The details still did not show the exposed rule.

![Screenshot 2026-04-21 122740](../img/objectives/o9/Screenshot%202026-04-21%20122740.png)

Additional details from the management NSG confirmed no public exposure.

![Screenshot 2026-04-21 122847](../img/objectives/o9/Screenshot%202026-04-21%20122847.png)

However, when inspecting the production NSG for <code>theneighborhood-rg1</code>, a particular rule with overly permissive access was found.

I used the following command:

~~~bash linenums="1" title="Show nsg-production-eastus"
az network nag show --name nsg-production-eastus --resource-group theneighborhood-rg1 | less
~~~

The rule named <code>Allow-RDP-From-Internet</code> is overly permissive since it allows unrestricted internet access to RDP port.

![Screenshot 2026-04-21 123529](../img/objectives/o9/Screenshot%202026-04-21%20123529.png)

I decided to inspect the specific rule using the command:

~~~bash linenums="1" title="Show Allow-RDP-From-Internet rule"
az network nsg rule show --resource-group theneighborhood-rg1 --nsg-name nsg-production-eastus --name Allow-RDP-From-Internet
~~~

As visible on the screenshot, I also inspected the <code>Allow-Jumpbox-Remote-Access</code> rule which revealed that the rule does not give public RDP access.

However, the <code>Allow-RDP-From-Internet</code> rule showed unrestricted internet access to RDP, confirming the misconfiguration.

The challenge was also confirmed a success.

![Screenshot 2026-04-21 123926](../img/objectives/o9/Screenshot%202026-04-21%20123926.png)

The challenge completed after identifying the risky rule.
