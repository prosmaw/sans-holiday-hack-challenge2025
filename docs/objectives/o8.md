## Solution

Barry asked me to use the Azure CLI to find the admin accidentally uploaded infrastructure config file.

The terminal session introduced the challenge and the Azure CLI environment.

![Screenshot 2026-04-20 192722](../img/objectives/o8/Screenshot%202026-04-20%20192722.png)

The first task was to list available resource groups using the command:

~~~bash linenums="1" title="List resource groups"
az group list -o table
~~~

The output showed the resource groups available in the subscription.

![Screenshot 2026-04-20 192855](../img/objectives/o8/Screenshot%202026-04-20%20192855.png)

Task 2 was to list storage accounts in the neighborhood resource group using the command:

~~~bash linenums="1" title="List storage accounts in rg-the-neighborhood"
az storage account list --resource-group rg-the-neighborhood -o table
~~~

The results showed the different storage accounts in the resource group.

![Screenshot 2026-04-20 193348](../img/objectives/o8/Screenshot%202026-04-20%20193348.png)

Apparently, there is a website in one of the storage accounts.

The next task was to check the blob service properties for each storage account.
The first storage account's blob service properties were checked using:

~~~bash linenums="1" title="Show blob service properties"
az storage blob service-properties show --account-name neighborhoodhoa --auth-mode login
~~~

This revealed that there is a website enabled for the account.

![Screenshot 2026-04-20 193603](../img/objectives/o8/Screenshot%202026-04-20%20193603.png)

The next task was to list containers in the <code>neighborhoodhoa</code> storage account with the command:

~~~bash linenums="1" title="List containers"
az storage container list --account-name neighborhoodhoa --auth-mode login
~~~

The container list showed a `$web` container.

![Screenshot 2026-04-20 193902](../img/objectives/o8/Screenshot%202026-04-20%20193902.png)


Task 5 was to list blobs in the `$web` container using the command:

~~~bash linenums="1" title="List blobs in $web"
az storage blob list --account-name neighborhoodhoa --container-name '$web' --output table --auth-mode login
~~~

The blob list included `iac/terraform.tfvars`.
![Screenshot 2026-04-20 194239](../img/objectives/o8/Screenshot%202026-04-20%20194239.png)

The next task was to download the tfvars file and review its contents with the command:

~~~bash linenums="1" title="Download terraform.tfvars"
az storage blob download --account-name neighborhoodhoa --container-name '$web' --name iac/terraform.tfvars --file /dev/stdout --auth-mode login | less
~~~

The download of the tfvars file shows that the file contains sensitive information.

![Screenshot 2026-04-20 195103](../img/objectives/o8/Screenshot%202026-04-20%20195103.png)


![Screenshot 2026-04-20 195133](../img/objectives/o8/Screenshot%202026-04-20%20195133.png)

The challenge was completed after the finding. I typed <code>finished</code> as required to complete the objective.

!!! tip "Prevention"
    - Never deploy Terraform state or `.tfvars` files into a publicly-served `$web` container (or any web root); keep IaC artifacts out of static-site deployment pipelines entirely.
    - Keep secrets like SAS tokens out of IaC variable files — pull them from Key Vault at apply-time instead of hardcoding them.
    - Scope any SAS token as tightly as possible (specific resource, read-only where practical, short expiry) instead of issuing broad read-write-delete tokens.
